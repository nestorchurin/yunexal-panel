# Changes — 2026-05-25

### Added
- **feat(env):** per-variable ENV permissions — admins/owners can toggle
  👁 Visible and ✏️ Editable per key; hidden values are masked in the API
  for regular users, non-editable keys are preserved server-side on save.
- **feat(settings):** SFTP connection panel on server settings page — shows
  host, port, username hint, path isolation note and Cloudflare Spectrum
  guidance; displays a disabled notice when SFTP is off.
- **feat(schedules):** per-server Scheduler tab (Pterodactyl-style) — create
  cron-driven tasks per container with three task types:
  - **Command** — runs a shell command inside the container via `docker exec`
    (`sh -c`), captures stdout/stderr;
  - **Power** — triggers start / stop / restart / kill on the container;
  - **Backup** — creates a `tar.gz` of the container's volume into a
    `backups/<prefix>-<timestamp>.tar.gz` file, accessible via the Files tab.
- **feat(schedules):** background Tokio runner polls due schedules every 30 s,
  immediately bumps `next_run_at` before spawning execution to prevent
  double-fire; each run is stored in `schedule_runs` with status and output.
- **feat(schedules):** run history pruning — keeps only the most recent N runs
  per server (configurable via **Max Schedule Run History** field on the server
  create / edit form, default 20).
- **feat(schedules):** **Run Now** button to trigger a schedule immediately
  outside its cron window.
- **feat(schedules):** human-readable cron preview in the create/edit modal
  (e.g. `0 3 * * *` → "Daily at 03:00").
- **feat(schedules):** `schedules` permission added to
  `SERVER_MEMBER_PERMISSIONS` (default `write`); page and API respect
  `schedules read` / `schedules write` checks.
- **feat(admin):** **Max Schedule Run History** field added to New Server and
  Edit Server admin forms; saved to `servers.max_schedule_runs` in SQLite.

### Fixed
- **fix(dashboard):** metrics (CPU/RAM) now correctly reappear after
  pressing Back on desktop; fixed bfcache race where frozen socket's
  `onclose` nulled the newly created WebSocket connection.
- **fix(console):** scoped `body { overflow: hidden }` and related flex
  rules to `body.yu-console-page`; class is added on console init and
  removed in `_yuPageCleanup`, so SPA navigation to Files/Settings no
  longer locks page scroll.
- **fix(console):** terminal viewport now reliably starts at the bottom
  on page load and after SPA navigation; added `term.scrollToBottom()`
  after every `fitAddon.fit()` call, and a one-shot `ResizeObserver` on
  `.con-term-bd` that fires fit + scroll once the container has its real
  height (handles CSS/flex layout settling after the initial timeout).
- **fix(files):** file input now captures `Array.from(this.files)` before
  clearing the input value, preventing FileList invalidation in some
  browsers; upload progress panel now hidden via `try/finally` so it never
  stays stuck on error.
- **fix(audit):** actor column now renders a purple avatar badge (initial
  circle + username) instead of plain bold text.
- **fix(schedules):** cron expressions now accept standard 5-field format
  (`min hour dom month dow`); internally converted to the 7-field format
  (`sec min hour dom month dow year`) required by the `cron` crate.
- **fix(spa):** CSS stylesheets are now awaited (`Promise.all` on `link.onload`)
  before the new page's DOM is attached — eliminates flash of unstyled content
  on first SPA navigation to any server tab.
- **fix(spa):** `schedules` tab added to `_isServerSidebarPath` regex — was
  falling back to a full page reload instead of SPA navigation.
- **fix(spa):** `schedules.js` now uses `readyState` fallback + `yu:page-shown`
  listener (matching `networking.js`/`files.js` pattern) instead of
  `DOMContentLoaded`, which never fires during SPA navigation.

### Performance
- **perf(console):** `console_page` handler no longer calls
  `docker::get_container()` on page load — Docker inspect removed from the
  render path entirely. Server name is read from the DB; container state is
  pushed to the client within 1 s via the existing WebSocket stats frame
  and applied by `updateControls()`.

### UI
- **fix(console):** "Terminal only" toggle (`bi-arrows-fullscreen`) is now
  mobile-exclusive — hidden via CSS on viewports ≥ 992 px; localStorage
  state is only restored on mobile so desktop layout is never affected.
- **fix(audit):** toolbar inputs (search, filter) lost styling on SPA
  navigation because CSS was scoped to `body.yu-server-audit` (set only on
  full page load); re-scoped to `.srv-audit-toolbar` so styles apply
  regardless of how the page is entered.

### DB
- **migration:** `ALTER TABLE servers ADD COLUMN max_schedule_runs INTEGER NOT NULL DEFAULT 20`
- **migration:** new `schedules` table (id, server_id, name, cron_expression,
  task_type, task_payload, enabled, last_run_at, next_run_at, created_at)
- **migration:** new `schedule_runs` table (id, schedule_id, started_at,
  status, output) with `ON DELETE CASCADE` from `schedules`
