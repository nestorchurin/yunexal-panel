# Snapshot - 25.05.2026 - 0.5.1

## feat(sftp): built-in SFTP server with Pterodactyl-style authentication

Added an embedded SFTP server that lets users manage server files via any
standard SFTP client, without exposing the host filesystem directly.

**Authentication:** username format `{server_id}.{panel_username}` (e.g.
`5.john`), password is the user's panel password verified via Argon2id.
Access is granted only to the server owner or members with `files=write`
permission.

**Volume isolation:** each SFTP session is chrooted to the server's volume
directory; path traversal (`../`) is rejected at the protocol level.

**Host key:** Ed25519 key is auto-generated on first start and stored
AES-256-GCM encrypted in `panel_settings`.

**Configuration:** enable/disable toggle and port (default `2022`) in
Admin → Settings → Operations → SFTP Access. Requires panel restart.

**Cloudflare:** two supported modes —
- *Spectrum (paid)*: add a TCP Spectrum rule on the SFTP port; clients use
  the proxied domain transparently.
- *DNS-only (free)*: point a separate `sftp.yourdomain.com` A record
  (grey cloud) directly at the server IP.

The Files tab of each server shows connection details (host, port, username
hint, password note) when SFTP is enabled.

## fix(docker): CPU limit 0 not saving on server edit

Setting CPU Limit to `0` (unlimited) or clearing the field on the server
edit page reported "saved" but the old limit persisted after a page reload.

**Root cause:** `update_container_resources` skipped the `--cpus` flag when
`cpu == 0.0`, so `docker update <id>` ran with no CPU-related arguments and
left the existing limit untouched.

**Fix:** `--cpus` is now always passed to `docker update`, including when the
value is `0`. `docker update --cpus 0` correctly removes the CPU limit.

## fix(settings): env vars not loading on first SPA navigation

Environment variables on the server settings page were blank when
navigating via the sidebar (SPA), and only appeared after a full
page reload.

**Root cause:** `<textarea id="env-raw">` was placed outside `<main
class="yu-main">`. The SPA router only moves `.yu-main` into the live
document; the textarea stayed in the detached DOMParser document, so
`readRawEnvFromDom()` returned an empty string.

**Fix:** The textarea is now inside `<main class="yu-main">`, so it
travels with the page node during SPA navigation. `initEnvPage()` also
calls `refreshEnvFromServer()` as a background fallback.

## feat(settings): owner-only env key editing

Panel admins can now only **change values** of existing env vars.
Adding, renaming, or deleting keys is restricted to the server owner
and root.

Previously `is_admin` controlled key-editing access, giving all panel
admins full control. A new `can_edit_keys` flag is computed from
server ownership (`owner_id == current_user_id`) or root role.

## feat(settings): GET /api/servers/{id}/env endpoint

New read endpoint returns the container's current env as a
newline-separated string. Used by `refreshEnvFromServer()` to keep
the settings page in sync after SPA navigation or after saving.

## feat(members): admin-only server member management

Adding, removing, and changing server member permissions now requires
the caller to be a panel admin in addition to having the `members`
write permission. Previously any user with write permission on
`members` could manage the member list.

## feat(db): automatic encryption migration on startup

On every panel startup, `migrate_legacy_encrypted_values` scans
`user_sessions.ip`, `image_env_overrides.env`, and
`panel_settings.service_api_key` for plaintext rows and encrypts them
with the cookie-secret-derived AES-256-GCM key. Already-encrypted
rows are skipped. This ensures panels upgraded from versions before
encryption was introduced are transparently migrated.

## feat(files): bulk download of selected files/folders

A **Download** button appears in the multi-select toolbar when one or
more files or directories are selected in the file manager. Selecting
a single file triggers a direct download; selecting multiple items
(or any directory) creates a `.tar.gz` archive on the fly and streams
it to the browser.
