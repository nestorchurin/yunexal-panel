### Database column encryption (AES-256-GCM)

Sensitive fields in the SQLite database are now encrypted at the application
level using AES-256-GCM. The encryption key is derived from `COOKIE_SECRET`
via SHA-256, so no additional secret is required.

Encrypted columns:
- `image_env_overrides.env` — per-image environment variable overrides
- `panel_settings.value` for key `service_api_key` — service API bearer token
- `user_sessions.ip` — client IP stored at login time

Existing plaintext rows are read transparently on every access
(`decrypt_if_encrypted` returns them as-is) and are re-encrypted on next write.
No manual migration is required on first startup with 0.5.1.

- `src/crypto.rs` *(new)*:
  - `derive_db_key(cookie_secret)` — SHA-256 of COOKIE_SECRET → 32-byte AES key
  - `encrypt(plaintext, key)` → `enc:v1:<base64(nonce||ct||tag)>`
  - `decrypt(ciphertext, key)` — strips prefix, verifies AES-GCM tag
  - `decrypt_if_encrypted(value, key)` — transparent: decrypts if `enc:v1:` prefix present, returns as-is otherwise (plaintext migration path)
  - `is_encrypted(value)` — prefix check

- `src/lib.rs`:
  - exposed `crypto` module as `pub mod crypto`

- `src/db/mod.rs`:
  - added `key_meta` table (`k TEXT PRIMARY KEY, v TEXT NOT NULL`)
  - added `verify_or_init_canary(pool, key)` — writes canary on first run, verifies on subsequent starts; returns an actionable error if `COOKIE_SECRET` was rotated without re-encrypting the DB

- `src/db/images.rs`:
  - `get_image_env` — decrypts value via `decrypt_if_encrypted`
  - `set_image_env` — always encrypts before storing
  - both functions now take `db_key: &[u8; 32]`

- `src/db/settings.rs`:
  - added `get_service_api_key(pool, db_key)` — reads and decrypts `service_api_key`
  - added `set_service_api_key(pool, value, db_key)` — encrypts and stores `service_api_key`
  - `get_panel_setting` / `set_panel_setting` remain unchanged (used for non-sensitive settings)

- `src/db/sessions.rs`:
  - `create_user_session` — IP is encrypted before INSERT; takes `db_key: &[u8; 32]`
  - `list_user_sessions` — decrypts IP of each returned row; takes `db_key: &[u8; 32]`

- `src/state.rs`:
  - added `db_key: [u8; 32]` field to `AppState`
  - `AppState::new` now takes `db_key` parameter

- `src/main.rs`:
  - derives `db_key` from `COOKIE_SECRET` on startup
  - calls `verify_or_init_canary` after DB init — fails fast with a clear message if key mismatch detected
  - passes `db_key` to `AppState::new`

- `src/auth.rs`:
  - `is_service_api_request_authorized` now reads the API key via `db::get_service_api_key` instead of raw `get_panel_setting`

- `src/handlers/admin.rs`:
  - `api_get_image_env`, `api_set_image_env`, `api_duplicate_image` — pass `&state.db_key`
  - `api_admin_set_setting` — routes `service_api_key` writes through `db::set_service_api_key` instead of the generic `set_panel_setting`

- `src/handlers/auth.rs`:
  - `login_submit` and `api_service_login` pass `&state.db_key` to `create_user_session`

- `src/handlers/create.rs`:
  - `create_server_submit` and `api_get_image_env_for_create` pass `&state.db_key` to `get_image_env`

- `src/handlers/dashboard.rs`:
  - `api_user_devices` passes `&state.db_key` to `list_user_sessions`

- `Cargo.toml`:
  - added `aes-gcm = "0.10.3"` and `sha2 = "0.10.8"`

### Key rotation support

- `src/bin/setup.rs`:
  - added `--rekey --old-secret <previous_COOKIE_SECRET>` command
  - verifies old key against canary before touching any data
  - re-encrypts all three column groups (`image_env_overrides.env`, `service_api_key`, `user_sessions.ip`) from old key → new key
  - updates the canary to the new key on completion
  - updated `--help` output to document the new flag

### sqlx TLS backend: tls-native-tls → tls-rustls

- `Cargo.toml`:
  - `sqlx` feature switched from `tls-native-tls` to `tls-rustls`
  - eliminates the OpenSSL dependency entirely (pure-Rust TLS stack)
  - required for `x86_64-unknown-linux-musl` cross-compilation on glibc hosts

### ISO build and installer TUI

- `scripts/iso/yunexal-installer.sh` *(new)*:
  - full branded TUI installer — runs on `tty1`/`ttyS0` instead of Alpine login prompt
  - 7-step wizard: requirements check, keyboard layout, networking, storage, setup profile, partition confirm, confirm changes
  - requirements step: internet connectivity check; offline mode requires explicit acceptance
  - keyboard step: lists available layouts and variants from `/usr/share/bkeymaps`, applies keymap live
  - networking step: interface selection, DHCP or static IP, timezone
  - storage step: system disk selection (EFI 512 MiB + SYS 100 GiB + DATA rest), optional additional data disks with ext4+prjquota
  - profile step: system hostname, root password, panel admin username/password
  - confirm partitions / confirm changes: shows full layout, requires explicit confirmation before erasing
  - `execute_install` (6 sub-steps):
    1. `yunexal-install prepare` — partition system disk
    2. `setup-alpine -f answers_file` — unattended Alpine base install
    3. `chpasswd` — root password on target
    4. Format additional data disks (ext4+prjquota), append to target fstab
    5. `yunexal-install finalize` — deploy panel runtime to target
    6. Write `.first-boot-admin` credentials (chmod 0600) + install `yunexal-firstboot` OpenRC one-shot service

- `scripts/iso/genapkovl-yunexal.sh`:
  - added installer TUI to apkovl overlay: copies `yunexal-installer.sh` → `/usr/local/sbin/yunexal-installer`
  - overrides `/etc/inittab`: `tty1` and `ttyS0` run the installer; `tty2`/`tty3` keep plain `getty` as escape hatches

- `scripts/iso/prepare-custom-tree.sh`:
  - removed `append_token_if_missing()` function that was injecting `apkovl=` into kernel cmdline
  - removing `apkovl=` from cmdline fixes apkovl not loading: Alpine's `prepare_apkovl()` in initramfs `init` requires a full path or auto-discovery; a bare filename fails `[ -f "$ovl" ]` silently
  - `nlplug-findfs` now auto-discovers `*.apkovl.tar.gz` from boot media (correct behavior)
  - added explicit `YUNEXAL_IMAGES_DIR` passthrough to `genapkovl-yunexal.sh` invocations

- `scripts/iso/Dockerfile.iso`:
  - removed `openssl-dev`, `openssl-libs-static`, `pkgconf` from musl builder stage
  - removed `OPENSSL_STATIC=1` and `PKG_CONFIG_ALL_STATIC=1` env vars
  - no longer required after `tls-rustls` switch
