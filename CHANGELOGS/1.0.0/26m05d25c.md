# Changes — 2026-05-25c

### Added
- **feat(backups):** "Upload Backup" button — restores a `.tar.gz` archive
  directly into the server volume; modal shows a red warning that all
  existing files will be deleted, a file dropzone, and an XHR upload
  progress bar; downloads disabled while restore is in progress.
- **feat(backups):** restore handler (`POST /api/servers/{id}/backups/restore`)
  — clears the volume directory and extracts the archive; tries direct
  extraction first, falls back to `docker run alpine` for root-owned volumes.
- **feat(audit):** actor role badge displayed next to username in the audit
  table — `root` (red), `admin` (amber), other named roles (grey); role is
  resolved at query time via LEFT JOIN with the `users` table.
- **feat(audit):** `get_admin_role_names()` — single DB query per request
  returns the set of role names that have `admin.access`; used for
  per-entry privilege comparison without per-row queries.

### Fixed
- **fix(audit):** IP addresses of admins and root users are now masked even
  when the viewer holds `audit.view_ip` — masking is applied if the actor's
  privilege level exceeds the viewer's (regular=0 < admin=1 < root=2);
  applies to both the paginated API and the downloadable `.log` export.
- **fix(backups):** backup archives are now stored in `{volume}_backups/`
  — a sibling directory adjacent to the container volume — instead of
  `{volume}/backups/` inside it; eliminates recursive inclusion, quota
  consumption, and loss of backups on factory reset.

### Performance
- **perf(backups):** `docker::backup_dir_for_volume()` helper added to
  `docker/files.rs`; all backup path resolution goes through this single
  function instead of ad-hoc `join("backups")` calls.

### Export
- **feat(audit/export):** downloaded `.log` now includes a `role=` field
  per line; IPs of privileged actors are exported as `[hidden]` for
  viewers with insufficient privilege level.
