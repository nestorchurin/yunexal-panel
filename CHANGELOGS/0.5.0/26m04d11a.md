### Storage orchestration — multi-disk + cross-filesystem migration
- `docker/edit.rs`: додано `recreate_with_updated_config_and_volume_source(...)` і внутрішній recreate з override source bind-mount
- `handlers/admin.rs`: додано lsblk-based інвентаризацію дисків (`LsblkRoot`, `LsblkNode`, `DiskCandidate`), визначення root/system disk і фільтрацію лише non-system partition candidates
- `handlers/admin.rs`: `api_admin_storage_mounts` повертає `prjquota_hint` для ext4 без `prjquota`
- `handlers/admin.rs`: новий endpoint `GET /api/admin/storage/disks` — список доступних несистемних партицій
- `handlers/admin.rs`: новий endpoint `POST /api/admin/storage/change-fs` — форматування non-system партицій у `ext4|xfs|btrfs` з safety-фразою `FORMAT /dev/...`, root-disk protection і audit log
- `handlers/admin.rs`: новий endpoint `POST /api/admin/storage/migrate` — orchestration міграції контейнера між дисками/ФС:
	- stop container (за потреби)
	- prepare target path/dataset/subvolume
	- copy data (`rsync`, fallback `cp -a`)
	- recreate container з новим bind source
	- update DB mapping (`servers.container_id`)
	- move `bw/<container_id>` state
	- restart + reapply bandwidth/isolation
	- reapply quota на target FS (XFS/ext4/ZFS/Btrfs) при наявності `yunexal.disk_limit`
- `handlers/admin.rs`: додано уніфіковану логіку `needs_permission` + `fix_command` для sudo NOPASSWD storage-операцій
- `handlers/mod.rs`: підключено нові admin routes:
	- `/api/admin/storage/disks`
	- `/api/admin/storage/change-fs`
	- `/api/admin/storage/migrate`
- `templates/admin.html`: у Settings залишено глобальну секцію **Disk filesystem conversion** (міграцію прибрано з global settings)
- `static/js/admin.js`: для settings залишено storage-оркестрацію дисків/ФС (`loadStorageDiskCandidates()`, `changeDiskFilesystem()`)
- `static/js/admin.js`: уніфіковано роботу з `suggested_path` через `_storageMountSuggestedPath()` для коректного multi-FS selection
