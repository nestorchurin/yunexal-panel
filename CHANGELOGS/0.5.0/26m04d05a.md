### XFS — повна підтримка
- `docker/quota.rs`: `xfs_pquota_mount(path)` — знаходить XFS mount з опцією `pquota`/`prjquota` через `/proc/mounts`
- `docker/quota.rs`: `apply_xfs_quota(volume_path, project_id, limit_bytes)` — записує проект у `/etc/projects` + `/etc/projid`, `xfs_quota project -s`, `xfs_quota limit bhard= bsoft=`
- `docker/quota.rs`: `remove_xfs_quota(project_id, volume_path)` — скидає ліміт до 0, прибирає записи з `/etc/projects` та `/etc/projid`
- `handlers/create.rs`: при наявності XFS+prjquota — `apply_xfs_quota` застосовується після реєстрації сервера
- `handlers/create.rs`: `api_xfs_check` — `GET /api/xfs-check` → `{"ok": bool}`, перевіряє чи є XFS+prjquota на системі
- `static/js/new_server.js`: при завантаженні форми перевіряє `/api/xfs-check`; якщо prjquota не активний — показує попереджувальний банер; при виборі диску виводить статус квоти (`prjquota active` / `no prjquota`)

### ZFS — повна підтримка
- `docker/quota.rs`: `zfs_dataset_for(path)` — знаходить ZFS dataset за точкою монтування через `/proc/mounts`
- `docker/quota.rs`: `apply_zfs_quota(volume_path, limit_bytes)` — `zfs create <parent>/<volume>` + `zfs set refquota=<bytes>`
- `docker/quota.rs`: `remove_zfs_quota(volume_path)` — `zfs destroy <dataset>`
- `handlers/create.rs`: при ZFS монтуванні — `zfs create` замість `mkdir`; `apply_zfs_quota` застосовується після реєстрації
- `handlers/admin.rs`: `is_zfs` детекція, `has_zfs` у JSON-відповіді `api_admin_storage_mounts`; для ZFS `suggested_path` = сам dataset
- `static/js/admin.js`: бейдж ZFS (блакитний), іконка `bi-layers`, субтекст `ZFS • N GiB free`; mount point не відображається, бо це dataset name
- `static/css/admin.css`: `.stor-opt-badge.zfs` — blue `#60a5fa`

### Btrfs — повна підтримка
- `docker/quota.rs`: додано `btrfs_mount_for(path)` — знаходить Btrfs mount для шляху через `/proc/mounts`
- `docker/quota.rs`: додано `apply_btrfs_quota(volume_path, limit_bytes)` — `btrfs quota enable` + `btrfs subvolume create` + `btrfs qgroup limit`
- `docker/quota.rs`: додано `remove_btrfs_quota(volume_path)` — `btrfs subvolume delete`
- `docker/mod.rs`: Btrfs функції експортовано
- `handlers/create.rs`: при створенні сервера на Btrfs монтуванні — `btrfs subvolume create` замість `mkdir`; після реєстрації — `apply_btrfs_quota`
- `handlers/admin.rs`: `api_admin_storage_mounts` — визначення `is_btrfs`, поле `has_btrfs` у JSON-відповіді
- `static/js/admin.js`: бейдж Btrfs (бурштиновий), іконка `bi-stack`, субтекст `Btrfs • N GiB free`
- `static/css/admin.css`: `.stor-opt-badge.btrfs` — amber `#fbbf24`

### ext4 — повна підтримка
- `docker/quota.rs`: додано `ext4_pquota_mount(path)` — знаходить ext4 mount з опцією `prjquota`/`prjjquota`
- `docker/quota.rs`: додано `apply_ext4_quota(volume_path, project_id, limit_bytes)` — `chattr +P -p <projid>` + `setquota -P`
- `docker/quota.rs`: додано `remove_ext4_quota(project_id, volume_path)` — скидає ліміти через `setquota`
- `docker/mod.rs`: ext4 функції експортовано
- `handlers/create.rs`: ланцюг квот розширено: XFS → ZFS → Btrfs → **ext4**; при ext4 директорія створюється через звичайний `create_dir_all`
- `handlers/admin.rs`: `is_ext4` детекція (ext4 + `/dev/`); `has_prjquota` тепер враховує `prjjquota` для ext4; поле `has_ext4` у JSON
- `static/js/admin.js`: бейдж ext4 (помаранчевий), іконка `bi-hdd-fill`, субтекст `ext4 • N GiB free`; якщо ext4 без prjquota — `no prjquota`
- `static/css/admin.css`: `.stor-opt-badge.ext4` — orange `#fb923c`
